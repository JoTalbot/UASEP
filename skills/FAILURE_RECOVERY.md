# Skill: Failure Recovery

When work fails:

1. Record the exact symptom and evidence in `.uasep/knowledge/FAILURES.md`.
2. Determine whether the failure is code, process, environment, or capability related.
3. Do not repeat an unchanged strategy.
4. Preserve working unrelated changes.
5. Find independent work that can continue.
6. If a rollback is needed, create a recoverable checkpoint or branch first when practical.
7. Mark unresolved work as BLOCKED or UNKNOWN rather than VERIFIED.
8. Update the handoff with the next recovery action.

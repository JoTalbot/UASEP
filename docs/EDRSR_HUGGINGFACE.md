# ЄДРСР → Hugging Face Dataset

## Цель

UASEP получает официальные открытые данные Единого государственного реестра судебных решений (ЄДРСР), сохраняет исходные архивы с provenance и публикует их в Hugging Face Dataset. Следующий слой может преобразовывать решения в Parquet/JSONL и строить embeddings для RAG.

## Источник

Официальный источник: Государственная судебная администрация Украины, наборы открытых данных ЄДРСР на `dsa.court.gov.ua` / `data.gov.ua`.

Для 2026 года набор обновляется ежедневно. На 30.08.2026 официальный размер архива `edrsr_data_2026.zip` составляет около 248.74 MB. Условия использования разрешают свободное копирование, распространение и использование открытых данных, включая коммерческое, при обязательной ссылке на источник.

## Архитектура

```text
ДСА України / Data.gov.ua
        |
        v
  CKAN metadata
        |
        v
 edrsr_data_YEAR.zip
        |
        +--> SHA-256/MD5 + manifest
        |
        +--> raw archive -> Hugging Face Dataset
        |
        +--> parser -> normalized Parquet shards
                           |
                           v
                     embeddings/vector DB
                           |
                           v
                       AIOS2 / RAG
```

## Репозиторий Hugging Face

Рекомендуемый тип: **Dataset**, например `JoTalbot/ua-edrsr`.

Рекомендуемая структура:

```text
raw/edrsr_data_2026.zip
raw/edrsr_data_2025.zip
manifests/2026.json
manifests/2025.json
structured/year=2026/*.parquet
structured/year=2025/*.parquet
README.md
```

Исходные ZIP не должны считаться поисковым индексом. Они нужны для воспроизводимости и provenance. Для AI-поиска используются структурированные shards.

## GitHub Actions

Workflow: `.github/workflows/edrsr-huggingface-sync.yml`.

Нужен GitHub Actions secret:

- `HF_TOKEN` — Hugging Face token с правом записи в Dataset repository.

И variable:

- `HF_DATASET_REPO` — например `JoTalbot/ua-edrsr`.

Текущая подключённая HF-сессия имеет только `read-repos`, поэтому публикация от имени пользователя через неё невозможна. Это не ошибка проекта: для записи нужен отдельный write-token, сохранённый только в GitHub Secrets.

## Режимы

1. **Raw sync** — безопасно публикует официальный архив и manifest.
2. **Structured ingest** — после подтверждения фактической структуры архива преобразует записи в Parquet shards.
3. **RAG build** — отдельный этап, который строит embeddings и индекс, не смешивая их с первичным государственным набором.

## Правила качества

- Не изменять исходные решения в raw-слое.
- Всегда сохранять URL источника, дату загрузки, размер и контрольную сумму.
- Не публиковать секреты, cookies или токены.
- Не считать AI-выводы частью официальной судебной практики.
- Для каждого результата RAG сохранять ссылку/идентификатор исходного решения.
- Не удалять анонимизацию, присутствующую в официальном наборе.
